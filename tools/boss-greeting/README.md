# BOSS 直聘｜按岗位定制打招呼 + 批量发送

两个脚本配合用：`greeting_gen.py` 按每个岗位的技术栈生成不同的话术，`send_boss.mjs` 用你已登录的 Edge 逐条发出去。

```
打招呼脚本/
├─ my_profile.json     我的信息（学校/届别/可实习时间/证据句）——先改这个
├─ greeting_gen.py     岗位 → 打招呼语（生成 + 质检 + 过滤）
├─ send_boss.mjs       打招呼语 → 批量发送（CDP 驱动 Edge）
├─ .boss-profile/      Edge 登录态（保留 BOSS 登录，别删）
├─ out_成都/           生成结果示例：greetings.xlsx（人工复核） + queue.json（待发队列）
├─ out_长三角/
└─ out_珠三角/
```

## 一、先生成话术

```powershell
cd 打招呼脚本
python greeting_gen.py --input "..\实习岗位清单_BOSS直聘.xlsx" --sheet 实习岗位 --out-dir out_成都
```

输出两份文件：

- `out_成都/greetings.xlsx` —— **务必先人工过一遍**。列里有「匹配度 / 字数 / 可发送 / 问题」，黑名单岗位（主播、兼职、电销、实习证明…）和重复岗位会被自动标掉。
- `out_成都/queue.json` —— 只含 `可发送=是` 的岗位，给发送脚本用。

话术逻辑：从岗位的「技术栈 + 要求」里抽关键词（SpringBoot、MySQL、Redis、并发…），按关键词挑对应的证据句，再套 4 种句式之一，同时确保 55–110 字、包含"每周几天 / 能实习几个月"。同一批里不会出现两条一模一样的话。

想改内容就改 `my_profile.json`：

```json
{
  "availability": "12 月起每周 4–5 天，能连做 3 个月以上",
  "evidence": {
    "Java": "独立写过 RBAC 权限 + 分层架构的 Java 项目，社团在用。",
    "MySQL": "MySQL 建表、索引和常用 SQL 都自己写。"
  }
}
```

⚠️ `evidence` 里**只能写你真做到的事**。面试官会顺着这句话问，写不实的东西等于给自己挖坑。

## 二、再批量发送

**先自检**（只验证输入链路，不发任何消息）：

```powershell
node send_boss.mjs --selftest --start
```

看到「✓ 输入链路正常」再往下。

**第二步演练**（只开页面、认按钮、打印要发的内容，不点发送）：

```powershell
node send_boss.mjs --queue out_成都/queue.json --limit 5 --dry-run --start
```

`--start` 会在没开调试端口时自动拉起 Edge（用 `.boss-profile`，保持登录）。

确认输出没问题后，先小批量真发 1 条看看效果：

```powershell
node send_boss.mjs --queue out_成都/queue.json --limit 1 --send
```

没问题再放量：

```powershell
node send_boss.mjs --queue out_成都/queue.json --send --limit 20 --delay-min 45 --delay-max 100
```

### ⚠️ 平台会先自动发一条「打招呼语」

BOSS 网页端点「立即沟通」时，**平台会自动发送你账号里设置的那句「打招呼语」**——就是聊天记录里反复出现的那句"您好，我是XX大学（XX）2028届本科生，本人熟悉Java，有Springboot，MySQL相关经验，希望收到您的回复。"。

这句来自账号设置，不是脚本发的，脚本改不了。所以现在：

- 脚本会检测这条自动消息并记进日志的 `autoMsg` 字段，然后才发定制句（HR 会看到两条）；
- 想让 HR 只看到一条，去 **BOSS App → 我的 → 设置 → 打招呼语**，把它改成一句短的（例如"您好，想了解一下这个岗位"），或者关掉自动发送。改完再跑脚本，定制句就是唯一一条。


### 参数

| 参数 | 说明 |
|---|---|
| `--queue` | 队列文件，默认 `queue_fresh.json` |
| `--limit` | 本次最多发多少条，默认 10 |
| `--delay-min/--max` | 两条之间的随机间隔秒数，默认 40–90 |
| `--send` | **真发**。不加就是演练 |
| `--dry-run` | 显式演练：只列计划，不开浏览器 |
| `--check` | 只验浏览器/页面/登录，不发送（等价 `env_check.mjs`） |
| `--daily-cap` | 每日成功上限，默认 18 |
| `--resume` | 从 `out/progress.json` 记录的断点继续 |
| `--allow-placeholder` | 放行含脱敏占位符的话术（默认拦截） |
| `--force` | 对「继续沟通」（已打过招呼）的岗位也发，默认跳过 |
| `--skip <file>` | 额外跳过名单，可直接传 `..\data\chat.json`（已沟通过的 114 家） |
| `--start` | 端口没开时自动启动 Edge |
| `--stop-on-error` | 连续失败几次停，默认 3 |
| `--log` | 发送日志，默认 `out/send_log.jsonl` |
| `--progress` | 断点文件，默认 `out/progress.json` |

### 如何停止 / 中途中断

这些脚本都是**一次性执行完就退出**的，正常情况下不需要你手动关：

- **随时停止**：在运行脚本的终端里按 `Ctrl + C`。安全，不会损坏队列、日志或登录态。
- **看起来卡住了？** 大概率是在等间隔，不是死循环。每条之间会打印 `…等待 50 秒`；`--limit 1` 发完就直接退出，不再空等。
- **关掉调试浏览器**：正常关窗口即可。**不要用任务管理器强杀 `msedge.exe`** —— 那会作废登录态，需要重新扫码。想用命令关，发一次 CDP `Browser.close` 即可。
- **中断后继续**：进度存在 `out/progress.json`，加 `--resume` 从断点接着跑。
- **中断时留了草稿？** 如果断在「写输入框」那一步，去那个会话里把输入框清空，再重跑。

## 三、它是怎么点的

1. 打开岗位详情页 `job_detail/xxx.html`
2. 读按钮文字：`立即沟通` = 没聊过；`继续沟通` = 已打过招呼（默认跳过，避免重复打扰）
3. 点按钮 → 平台先自动发一条账号里的「打招呼语」→ 跳进 `web/geek/chat` 并选中该 HR
4. 聚焦 `#chat-input`，用 CDP `Input.insertText` 模拟真实输入，**写完先读回来核对**，不一致就换方式重试（最多 3 次）
5. 等 `button.btn-send` 从 `disabled` 变为可用，点发送
6. 校验「输入框已清空」**且**「最后一条我方消息 = 刚发的内容」，两条都满足才算成功；写进 `send_log.jsonl`
7. 随机等待 40–90 秒再下一个

## 四、风控（很重要，别跳过）

BOSS 对高频、模板化、异常节奏的招呼有风控，**最坏结果是账号被限制沟通**。建议：

- 每天 **不超过 30–40 条**，间隔 **不少于 40 秒**，不要 24 小时连轴跑；
- 只在 **9:00–20:00** 跑，HR 下班后发的没人看；
- 话术不要全军覆没式雷同——脚本已经做了随机句式，但**同一个岗位类别别一天发超过 15 条**；
- 出现「安全验证 / 访问过于频繁」字样时脚本会自动停，**不要绕过验证码**，手动处理后再跑；
- 前几条务必人工看结果，确认发出去的是你想要的文字。

## 五、已验证到什么程度

`node send_boss.mjs --selftest` 实测通过：打开会话、写入文字、**读回核对一致**、发送按钮由 `disabled` 变可用、清空草稿（全程未发送）。

**未实测**：最后那一下 `btn.click()` 的真实投递——那会给真实 HR 发消息。第一次请用 `--limit 1 --send`，自己盯着发一条，确认无误再放量。
