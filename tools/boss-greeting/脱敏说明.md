# 脱敏说明（2026-11-17）

这个目录现在是一份**可外传的脱敏版本**。真实姓名、学校、专业已替换为占位符，登录态目录已删除。
要恢复成能真实投递的版本，按下文「恢复」一节操作。

## 一、做了什么

| 对象 | 处理 | 数量 |
|---|---|---|
| `.boss-profile/`（登录态） | 备份后删除 | 3613 文件 / 881 MB，含 `Cookies`、`Login Data`（保存的密码）、`Local State` |
| 身份信息（姓名 / 学校 / 专业） | 替换为占位符 | **31 个文件 / 2318 处** |
| `out/progress.json` | 删除 | 派生数据，且是登录失效时产生的无意义记录 |

替换规则（原文字面量本身也是敏感信息，此处不再复现）：

| 类别 | 替换为 |
|---|---|
| 真实校名（带校区后缀的全称） | `XX大学（XX）` |
| 真实校名（简称） | `XX大学` |
| 真实姓名 | `张三` |
| 真实专业名 | `XX专业` |

需要核对具体字面量时，看 `sanitize_identity.mjs` 顶部的 `MAP` 表——那里的原文用 `\u` 转义存放，
文件里没有明文，所以它不参与脱敏也不会泄露（但它仍能正常替换）。

## 二、备份在哪

```
backup_20261117_全量/                    ← 脱敏前的完整快照（131 个文件 + .boss-profile）
  ├─ .boss-profile/                      ← 登录态（Cookies / Login Data）
  ├─ my_profile.json                     ← 含真实姓名与学校
  ├─ queue*.json / out/*                 ← 含真实话术
  └─ *.mjs *.py *.md                     ← 脱敏前的脚本
backup_20261117/                          ← 更早一次（P0/P1 改造前）的脚本备份
```

⚠️ **`backup_20261117_全量/` 里仍是明文敏感数据**，这是刻意的（备份的意义）。
它不能外传、不能进仓库、不能上传网盘。确认不再需要后，直接删掉整个 `backup_20261117_全量/` 即为彻底清理。

## 三、脱敏带来的两个后果

1. **队列话术变成了占位文本**，例如：
   > 您好，我是XX大学（XX）2028届本科生，本人…

   直接发出去，HR 收到的是占位符。为此加了一道闸门：

   - `send_boss.mjs` 和 `send_by_company.mjs` 检测到占位符会**拒绝发送**（exit 1）
   - 队列里只有部分占位时，逐条跳过并在结尾汇总
   - 确需强行放行：`--allow-placeholder`（一般不该用）

2. **`verify_new.mjs` 不再比对内容**。`my_profile.json` 里的标识全成了占位符，
   拿它去匹配真实历史消息必然全部不命中，所以该脚本现在只报「有没有消息」，不会再谎报「没有消息」。
