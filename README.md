# 实习投递助手（intern-helper）

**该项目由人工智能软件（Deepseek Harness、WorkBuddy等）辅助生成**

一个把自己找实习的过程做成系统的后端项目：**岗位库 + 内置模板与 AI 润色的话术生成 + 投递记录 + 转化统计**。

> 背景：找实习时每天要投几十家，岗位信息散落在表格里、话术每次手写、投了多少/回了多少全靠回忆。这个项目把这些流程沉淀成一套可查询、可统计的系统。

> **免责声明**：本项目仅用于个人求职信息管理与话术草稿生成，不含任何自动发送功能。
> 请勿用于违反目标网站服务条款的行为。

## 功能

1. **岗位库**：增删查、**按省 / 市 / 区三级筛选**、关键词搜索、**游标分页**（深翻页恒定耗时）+ **跳转到指定页**
2. **结构化字段**：自动解析实习时长（月）、每周出勤（天）；薪资录入区分**日薪 / 月薪**两种方式，统一折算成**最低日薪 / 最高日薪**（不取平均）
3. **话术生成**：读「个人资料」里的学校/学历/专业/年级/技能生成话术，使用**简洁 / 正式两套内置模板**；技能句按岗位名/技术栈/要求原文匹配；时长与出勤后端硬上限 **12 个月 / 每周 7 天**，同时展示建议「实习最好不超过6个月，每周最好不超过6天。」；可选接入 DeepSeek 在模板草稿上做 AI 润色，失败、校验不过或额度不足自动回退模板
4. **投递记录**：每次投递落一条记录（公司、岗位、实际话术、时间、成功与否），并把岗位状态改成「已联系」
5. **统计**：今日/累计投递数、成功率、岗位库状态分布、各公司投递 Top
6. **数据同步**：JSON 批量导入（按「公司 + 岗位」去重）+ **导入批次留痕** + **定时扫描投放目录自动入库**
7. **岗位类型区分**：按日薪与标题自动识别「实习 / 社招」，列表默认只看实习岗，可切换查看社招
8. **页面**：列表页（筛选、排序、跳页、生成话术、编辑、删除）+ 新增/修改岗位表单页
9. **AI 岗位信息抽取**：在新增页粘贴页面正文/HTML，或直接贴岗位网址由本机脚本取正文；抽取公司、岗位、地点、薪资、时长、出勤、要求与技能标签。只生成草稿、不落库，字段必须在原文中有依据，找不到就留空

## 数据库

由 JPA 自动建（`ddl-auto: update`）：

| 表 | 说明 |
|---|---|
| `job` | 岗位：公司、岗位名、**省/市/区**、原始地点、薪资、**实习月数/出勤天数/最低日薪/最高日薪**、链接、技术栈、要求原文、状态（NEW/CONTACTED） |
| `greeting_rule` | 话术规则：正则 → 技能句 → 方向名，可改数据库直接生效 |
| `application_record` | 投递记录：jobId、公司、岗位、话术、成功与否、时间 |
| `candidate_profile` | 个人资料（单行）：学校、学历、专业、年级、技能、佐证、可实习时长、每周出勤、句式风格 |
| `ai_usage` | 模型调用用量：本机实例、扣费模式、token 数、金额、提示词版本 |
| `app_setting` | 系统设置（key-value）：引擎、模板、模型连接、单价；数据库值优先于环境变量 |
| `import_batch` | 导入批次：来源、渠道（MANUAL/SCHEDULED）、收到/新增/跳过、时间 |

## 运行

```bash
# 1. 建库
mysql -uroot -p -e "CREATE DATABASE intern_helper DEFAULT CHARACTER SET utf8mb4;"

# 2. 配置（用环境变量，不要把密码提交进仓库）
export MYSQL_USER=root
export MYSQL_PASSWORD=你的密码
# 可选：候选人信息，不配就用占位值「某大学 / 2028届」
export CANDIDATE_SCHOOL=你的学校
export CANDIDATE_GRADE=2028届

# 可选：AI 润色。默认 RULE 仅用内置模板，不调用模型
export GREETING_ENGINE=RULE              # RULE / AI / HYBRID
export DEEPSEEK_BASE_URL=https://api.deepseek.com
export DEEPSEEK_MODEL=your-model
export PLATFORM_DEEPSEEK_API_KEY=平台默认密钥
# 单价单位：元 / 1M tokens；输入价分缓存命中 / 未命中两档
export DEEPSEEK_PRICE_INPUT_CACHE_HIT_PER_1M=缓存命中输入单价_元每百万token
export DEEPSEEK_PRICE_INPUT_CACHE_MISS_PER_1M=缓存未命中输入单价_元每百万token
export DEEPSEEK_PRICE_OUTPUT_PER_1M=输出单价_元每百万token
# 兼容旧单位 元 / 1K tokens：DEEPSEEK_PRICE_INPUT_PER_1K 等仍可用，仅当 1M 单价未配置时生效
# 用户自带密钥：填写后进入 BYO 模式，跳过 0.1 元默认额度
# export DEEPSEEK_API_KEY=用户自己的密钥

# 3. 打包 & 启动
mvn clean package -DskipTests
java -jar target/intern-helper-0.12.1.jar

# 4. 打开页面
http://localhost:12231
```

## 数据同步怎么用

**方式一：手动导入**

```bash
curl -X POST "http://localhost:12231/api/import/jobs?source=manual" \
  -H "Content-Type: application/json; charset=utf-8" \
  --data-binary "@sample_jobs.json"
```

**方式二：丢文件自动导入**

把 `{"jobs":[...]}` 格式的 JSON 丢进 `import-drop/` 目录，系统每 5 分钟扫描一次，导入后自动把文件移到 `import-drop/imported/`。

爬虫脚本只要负责把文件写进这个目录，两边就解耦了：

```
python 抓取 → 写入 import-drop/jobs-2024xxxx.json
                    ↓ 定时扫描（5 分钟）
              job 表 + import_batch 批次记录
```

**脚本想用 AI 抽取也可以**：抓取脚本拿到客户提供的页面后，既可以在脚本侧自己整理字段，也可以调用同一个抽取接口拿草稿，再按标准 `{"jobs":[...]}` 写入投放目录；系统侧导入链路不需要改：

```bash
curl -X POST "http://localhost:12231/api/jobs/extract" \
  -H "Content-Type: application/json; charset=utf-8" \
  --data-binary "@page-text.json"
# page-text.json: {"pageText":"<抓取到的页面正文或 HTML>"}
```

返回的是字段草稿（含 `warnings`），脚本合并进标准导入格式即可。系统不负责后端直接抓 URL，反爬与合规仍由脚本侧承担。

### 常见问题：岗位详情页选不中 / 复制不到「岗位要求」

BOSS 直聘等站点会用 `user-select: none` 或 iframe 阻止常规选择复制，但 DOM 里的文本仍可通过浏览器开发者工具拿到，**不需要改代码**：

1. 打开岗位页，先滚动到底，确认「岗位要求 / 职位描述」已加载出来；
2. 按 `F12` → **Console**，执行 `copy(document.body.innerText)`，剪贴板里就是全页可见文本（能绕过 `user-select: none`）；也可执行 `copy(document.body.innerHTML)` 复制 HTML，系统会自动去掉标签和脚本；
3. 若仍缺岗位要求：在 Console 顶部下拉框切到对应 iframe 后重试；或在 **Elements** 里 `Ctrl+F` 搜「岗位要求 / 职位描述」，右键该节点 → **Copy** → **Copy outerHTML**，把这一段粘进抽取框；
4. 可以分两次填：先粘整页文本拿公司/岗位/薪资，再粘岗位要求那段补 JD 与技能标签。第二次会再消耗一次模型额度，未识别的字段会保留原值不被覆盖。

**如果一按 `F12` 网页就退出**：多半是站点另有反调试脚本（与你看到的那段 `Warlock` 埋点 SDK 无关）。可换用不进开发者工具的办法：

- **先开工具再导航**：新标签页先按 `F12` 打开控制台，再在地址栏输入岗位链接回车；部分反调试只在页面加载时检测一次。
- **Edge 沉浸式阅读器**：打开页面按 `F9`，去掉页面脚本与干扰元素后再复制文本。
- **另存网页**：`Ctrl+S` 选「网页，全部」保存到本地，用记事本 / 浏览器打开保存的 HTML，搜「岗位要求 / 职位描述」复制中文正文。
- **另存 PDF**：`Ctrl+P` → 目标选「另存为 PDF」，再从 PDF 里复制文字。
- **换 Firefox**：同一链接在 Firefox 里打开并开开发者工具，有时不会触发 Chrome 下的退出逻辑。

**「岗位要求是不是图片」的验证结论**：服务端直接请求该链接会被 302 到 `web/passport/zp/security.html` 安全验证页，拿不到岗位正文，因此**无法从服务端确认它是文本还是图片**；阅读器里也看不到，只说明它不在常规可读 DOM 里。本地可这样判定：`Ctrl+S` 保存「网页，全部」后用记事本搜「岗位要求 / 职位描述」——搜到中文正文就是 DOM 文本（可能是自定义字体混淆）；只搜到 `<img>` 链接就是图片；搜到 `\ue000` 一类私用区字符则是字体反爬。若是图片，用 PowerToys 文本提取器（Win+T）或手机 OCR 识别截图即可，识别出的文字粘回抽取框仍能被事实溯源校验。

**想让脚本代劳（第二期，已提供）**：现在可直接在网页点「按网址识别」，无需手敲命令；后端会调用本机 `..\\打招呼脚本\\extract_job.mjs`，复用 `.boss-profile` 登录态打开链接、取正文、解析回填。命令行方式仍保留（加 `--import` 才写标准 JSON 到投放目录）。两者遇到安全验证都会停下来等你手动处理，不绕过验证码；服务端仍不直接抓 URL。脚本用法见 `..\\打招呼脚本\\README.md` 第七节。

## 几个实现上的点

**1. 规则放数据库，不放代码**
话术的技能句匹配规则（测试 / 数据 / 算法 / AI / Go / 全栈 / 微服务 / 中间件 / 运维）存在 `greeting_rule` 表，按 `priority` 升序匹配，命中即用。想加一种岗位方向，插一条数据就行，不用改代码重新发版。

**2. 时长解析 + 边界截断**
岗位要求里常见「5天/周、6个月」。用正则解析出来，再做 clamp：月数限制在 2–12，天数限制在 2–7。超出部分由后端强制截断；同时页面和接口返回产品建议「实习最好不超过6个月，每周最好不超过6天。」，建议不写入对外话术。

**3. 深分页用游标，跳页才用 offset**
顺序翻页走 `where id < :cursor order by id desc limit 16`，深翻页耗时恒定；只有「跳转到第 N 页」「按字段排序」时才用 offset，因为这类需求本身就必须知道偏移量。数据量再大时可以把跳页限制住，或者按城市分片。

**4. 薪资格式统一折算成日薪区间**
岗位薪资格式很杂：`200-400元/天`、`4-6K`、`20-40K·15薪`、`面议`。统一折算成「最低日薪 / 最高日薪」两列（月薪按 21.75 个工作日），**不做平均**：平均值会把「200-400」和「300」压成同一个数，实际的区间差别很大。两列各自可排序，解析不出的为 null，排序时排最后。

**5. 实习岗 / 社招 自动区分**
放宽关键词抓岗位时会混进社招（月薪 20K+、P6/P7、3-5 年）。判定规则：标题含「实习」→ 实习；否则日薪 > 900（≈月薪 2 万）或标题命中「高级/资深/P6/P7」→ 社招。列表默认只查 category=INTERN，想看全部就切下拉。规则是启发式的，标错了可以在编辑页手动改。

**6. 地点拆成省 / 市 / 区**
原始数据是「广州海珠区」这种混在一起的字符串，既没法按省筛，也用不上索引。用内置城市字典拆成三段存三个字段，前端做成三级联动，查询走 `(province, city)` 精确匹配。历史数据在启动时自动回填。

**7. 导入去重 + 批次留痕**
按「公司 + 岗位名」判重；每次导入写一条 `import_batch`，页面顶部就能显示「最近同步：xx 时间 · 新增 N 条」。

**8. 分层与异常**
Controller 只做参数接收和组装，业务在 Service，数据访问在 Repository；全局 `@RestControllerAdvice` 统一返回 `{code, message}`，避免异常直接抛到页面。类型错误 400、路径不存在 404、方法不支持 405、唯一键冲突 409。

**9. 本机工具的安全边界**
服务只监听 `127.0.0.1`（`server.address`），不对局域网开放；不提供跨源访问（CORS 默认拒绝），阻止任意站点读取本机数据；统一设置 5 个安全响应头（`nosniff` / `DENY` / `no-referrer` / `no-store` / 宽松 CSP 兼容内联脚本）。定位是单人本机工具，**无鉴权体系**——如需公网访问应放在反向代理后并自行加认证。

### v0.11.1（2026-11-21）

**主题：修复新功能测试发现的阻断性缺陷，并补强批量端点的异常输入处理。**

- **批量端点异常输入**：四个批量端点的 errors 统一为字符串键的 Map，过滤 ids 中的 null 元素（原 null key 使 Jackson 序列化失败 → 500）。
- **超长话术**：投递记录 message 列扩至 2000 字（与话术保存校验一致）；批量标记已投增加前置长度校验，超限写入 errors 不落库。
- **非法 ID 错误键**：由数组索引改为原始 ID 字符串，文案统一中文，不再透传原生异常。
- **跨页选择提示**：翻页重建列表后同步批量栏计数与实际选中，避免提示误导。

### v0.10.4（2026-11-20）

**同版本补充：剩余三条问题（版本号不变）**

- **AI 自由生成架构改造（第 1 条，根本解法）**：旧实现把整份个人资料交给模型自由创作，事实靠事后词典校验拦截，而技术词是开放集合、无法穷举，词典只能兜底。新架构把「事实的产生方式」改为确定性：
  1. 提示词只给模型一组占位符（`{{school}}`、`{{skillClause}}`、`{{months}}`、`{{days}}` 等），**不含任何真实事实值**；模型只负责组织语序与连接词，输出一段「表达骨架」。
  2. 骨架先过结构校验：只允许白名单占位符、必须含 5 个核心事实槽位、不得写死月数/天数。
  3. 后端用 `GreetingTemplateService.renderText()` 把占位符替换为确定性事实值——模型无权决定学校、技能、数字的具体内容。
  4. 回填后再跑一次事实校验（白名单 + 词典兜底），拦截连接词里夹带的未授权技术词；任一环节失败即回退内置模板。
  - 效果：攻击面从源头收敛，模型没有机会写出具体编造事实；词典从「唯一防线」降为「最后一道网」。技术词别名漏检的根因（词典不完备）不再影响事实正确性。
- **投递失败状态越界（第 2 条）**：`JobService.nextStatusAfterFailure(current)` 抽出纯逻辑——失败时只有当前为 `NEW`/null 才归一为 `NEW`，`SKIPPED`/`CONTACTED` 保持不变，不再把已跳过/已联系岗位打回待投。
- **导入绕过校验（第 3 条）**：`importJobs()` 逐条调用 `validateJob(job, false)`，非法条目（越界月数天数、非法枚举、空必填）跳过并记 warn，不中断整批，与 `create()` 抛异常中断的语义区分。
- **设置页风险提示**：默认模板选择「AI自由生成」时弹出风险告知窗口（纯告知、不强制确认，可点按钮/遮罩/Esc 关闭），说明事实由系统回填但语气由模型生成、需 AI/HYBRID 模式、按量计费。
